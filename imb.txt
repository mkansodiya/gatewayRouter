## 1. Overview

IMB Gateway processes **UPI-based payments** (India — GPay, PhonePe, Paytm & more). Unlike OkPay, IMB uses a **simpler token-based authentication** (no signature generation required). The integration involves two operations:

| Operation | HTTP Method | Endpoint |
|---|---|---|
| Create Payment Order | `POST` | `{IMB_HOST_URL}` (configured in settings) |
| Receive Payment Callback | `POST` | `{YOUR_SITE}/wp-json/pmpro-imb/v1/imb-handler` |

## 3. API Endpoint: Create Payment Order

When a user submits the checkout form, the plugin sends a `POST` request to the configured **Host URL** to create a payment session and get a redirect URL.

### Request

- **URL:** `{IMB_HOST_URL}` _(the value saved in the Host URL setting)_
- **Method:** `POST`
- **Content-Type:** `application/x-www-form-urlencoded`

> [!NOTE]
> There is **no signature/sign field** required. Authentication is done purely via the `user_token`.

### Request Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `user_token` | string | ✅ | Your IMB API Key (`pmpro_imb_api_key`) |
| `amount` | float/string | ✅ | Payment amount (taken from the order's `InitialPayment`) |
| `order_id` | string | ✅ | Unique order reference code generated by your system |
| `redirect_url` | string | ✅ | URL to redirect user after successful payment (confirmation page) |

### Example Request (PHP/cURL)

```php
$payload = [
    'user_token'   => 'YOUR_IMB_API_KEY',
    'amount'       => '499',
    'order_id'     => 'ORD1234567890',
    'redirect_url' => 'https://yoursite.com/confirmation/?level=2',
];

$ch = curl_init('https://your-imb-host-url.com/create-order');
curl_setopt($ch, CURLOPT_POST, true);
curl_setopt($ch, CURLOPT_POSTFIELDS, http_build_query($payload));
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
curl_setopt($ch, CURLOPT_HTTPHEADER, ['Content-Type: application/x-www-form-urlencoded']);
$response = curl_exec($ch);
curl_close($ch);

$result = json_decode($response, true);
```

### Success Response

```json
{
  "status": true,
  "result": {
    "payment_url": "https://pay.imb-gateway.com/session/abc123xyz"
  }
}
```

| Field | Type | Description |
|---|---|---|
| `status` | boolean | `true` = success, `false` = error |
| `result` | object | Contains payment data |
| `result.payment_url` | string | The **payment page URL** — redirect the user here immediately |

### Error Response

```json
{
  "status": false,
  "message": "Invalid API Key or unauthorized request"
}
```

### Validation Rules (Plugin-Side)

The plugin validates the API response with these checks before redirecting:

| Check | Behavior on Failure |
|---|---|
| Response is not a valid array | `wp_die('Invalid response from IMB')` |
| `status` key missing | `wp_die('Invalid response from IMB')` |
| `result` key missing | `wp_die('Invalid response from IMB')` |
| `status !== true` | `wp_die('Error from IMB: ' + message)` |
| `result.payment_url` empty | `wp_die('Invalid response from IMB: URL not found in data')` |

## 4. Webhook / Payment Callback (REST API)

After the user completes payment on the IMB payment page, IMB **POSTs back** to your site's REST API endpoint to notify you of the result.

### Your Callback URL (fixed, no configuration needed)

```
POST https://yoursite.com/wp-json/pmpro-imb/v1/imb-handler
```

> [!IMPORTANT]
> This URL is **automatically registered** by the plugin via WordPress REST API. You must share this exact URL with the IMB team so they can configure it as the callback/notify URL.

### Incoming POST Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `order_id` | string | ✅ | The `order_id` you sent in the Create Order request |
| `status` | string | ✅ | Transaction status — must be `"SUCCESS"` to activate membership |

> [!NOTE]
> The `permission_callback` for this endpoint is set to `__return_true`, meaning it is **publicly accessible** — no authentication header required from IMB's side.

### Callback Handler Logic

When the callback is received, the plugin:

1. Reads `order_id` from `$_POST` — dies if missing.
2. Reads `status` from `$_POST` — dies if missing.
3. **If `status !== 'SUCCESS'`** → `wp_die('Transaction not completed')` — no membership change.
4. Looks up the local order by `order_id` code — dies if not found.
5. Calculates membership expiration date from the level settings.
6. Calls `pmpro_changeMembershipLevel()` to activate the user's membership.
7. Sets order `status = 'success'` and saves it.
8. Sends checkout confirmation email to the user via `PMProEmail::sendCheckoutEmail()`.
9. If membership level change **fails** → sets order `status = 'error'` and `wp_die('Failed...')`.

### PHP Callback Handler Example (standalone)

```php
// Received at: POST /wp-json/pmpro-imb/v1/imb-handler

$order_id   = $_POST['order_id'] ?? '';
$txn_status = $_POST['status'] ?? '';

if (empty($order_id))   die('Order ID not found.');
if (empty($txn_status)) die('Transaction status not found.');
if ($txn_status !== 'SUCCESS') die('Transaction not completed');

// Look up the order by order_id (order code)
$order = get_order_by_code($order_id); // your implementation

if (empty($order)) die('Invalid Order.');

// Activate membership
$success = activate_membership($order);

if ($success) {
    // Mark order as success, send confirmation email
    exit; // End cleanly
} else {
    die('Failed to change membership level. Try Again.');
}
```

## 5. Order ID Generation

The plugin generates a **numeric-only order ID** using this logic:

```php
function generateNumericOrderId(): string {
    $micro = substr(str_replace('.', '', microtime(true)), -7); // Last 7 digits of microtime
    $rand  = mt_rand(100, 999);                                  // 3-digit random number
    return $micro . $rand;                                       // e.g. "1234567890" (10 chars)
}
```

This means your `order_id` values will always be **10-digit numeric strings**. Ensure your system can handle this format when looking up orders from the callback.

## 6. Payment Flow (End-to-End)

```mermaid
sequenceDiagram
    participant User
    participant YourServer
    participant IMBAPI

    User->>YourServer: Submits checkout form (gateway=imb)
    YourServer->>YourServer: Create local order (status=review), generate order_id

    IMBAPI-->>YourServer: { status:true, result: { payment_url } }
    YourServer->>User: wp_redirect to payment_url
    User->>IMBAPI: User completes UPI payment

    YourServer->>YourServer: Validate order_id, activate membership level
    YourServer->>YourServer: Set order status=success, send confirmation email
    YourServer->>User: User sees confirmation page (via redirect_url)
```

## 7. Differences vs OkPay Gateway

| Feature | IMB | OkPay |
|---|---|---|
| Authentication | Bearer token (`user_token`) | MD5 Signature (`sign`) |
| Webhook signature verification | ❌ None | ✅ MD5 sign check |
| Callback URL | Fixed WP REST route `/wp-json/pmpro-imb/v1/imb-handler` | Query param `/?pmpro_okpay_webhook=1` |
| Status polling / cron | ❌ Not present | ✅ Every minute + hourly |
| Payment status field | `status = "SUCCESS"` (string) | `status = 1` (integer) |
| Amount type | Float (from `InitialPayment`) | Integer string (no decimals) |
| API endpoints | 1 (create order only) | 2 (create + query) |

## 8. Notes & Edge Cases

| Topic | Detail |
|---|---|
| **Callback URL sharing** | Share `https://yoursite.com/wp-json/pmpro-imb/v1/imb-handler` with IMB to configure as their notify URL |
| **No query/polling API** | IMB has no status query endpoint. Payment confirmation relies entirely on the callback. |
| **Status value is a string** | Check `status === 'SUCCESS'` (uppercase string), not an integer |
| **No signature required** | Do NOT add a `sign` field to IMB requests — there is no signature algorithm for IMB |
| **Order ID is numeric** | 10-digit numeric string. Must be stored and matched exactly on callback |
| **Redirect URL** | Set to the PMPro confirmation page with the membership level ID as a query param |
| **Missing credentials** | Plugin `wp_die()`s immediately at checkout if `imb_api_key` or `imb_host_url` are empty |
| **Email on success** | The plugin automatically sends the PMPro checkout confirmation email after membership activation |
